# Bank Term Deposit Subscription Predictor

## a. Problem statement

Portuguese retail banks run outbound phone campaigns to sell term deposit
products. Each call is expensive, so knowing in advance which customers are
likely to say yes lets the bank prioritize call lists and reduce wasted
contacts. This project predicts, from a customer's demographics, account
information, and current/previous campaign contact history, whether they
will subscribe to a term deposit (`deposit` = **yes**/**no**) — a **binary
classification** problem.

## b. Dataset description

- **Source**: UCI Machine Learning Repository — Bank Marketing dataset
  (Portuguese bank direct-marketing phone campaigns, 2008–2010).
- **File**: `data/bank.csv`
- **Rows**: 11,162
- **Raw columns**: 17 (16 features + target `deposit`)
- **Target**: `deposit` — whether the client subscribed to a term deposit (yes/no)
- **Raw feature groups**:
  - Demographics: `age`, `job`, `marital`, `education`
  - Financial standing: `default`, `balance`, `housing`, `loan`
  - Current campaign contact: `contact`, `day`, `month`, `duration`, `campaign`
  - Previous campaign history: `pdays`, `previous`, `poutcome`
- **Engineered features** (see `preprocessing.py`), added to give the models
  more directly usable signal than the raw numeric columns:
  - `age_band` — life-stage bucket (under_25, 25_34, 35_44, 45_54, 55_64, 65_plus)
  - `balance_tier` — quantile bucket of account balance (very_low → very_high)
  - `was_contacted_before` — flag derived from `pdays == -1` ("never contacted before")
  - `campaign_intensity` — `campaign` clipped at 10, to bound outlier contact counts

After engineering, the model matrix uses **11 categorical + 9 numeric = 20
input columns** (comfortably over the 12-feature minimum), on **11,162
instances** (over the 500-instance minimum).

## d. Models used

All 6 models are trained on the same engineered dataset with an 80/20
stratified train/test split (`random_state=42`), via `train_models.py`.
Categorical columns are one-hot encoded and numeric columns standardized
with a shared `ColumnTransformer` (`preprocessing.py`), fit on the training
split only.

- **Logistic Regression** — linear baseline, `max_iter=1000`
- **Decision Tree Classifier** — `max_depth=8`
- **K-Nearest Neighbor Classifier** — `n_neighbors=15`
- **Naive Bayes** — GaussianNB (features are a mix of one-hot + standardized
  continuous; GaussianNB is used since MultinomialNB requires non-negative
  count-like features, which standardized/one-hot data isn't)
- **Random Forest (Ensemble)** — `n_estimators=300`, `max_depth=12`

### Observations

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Strong, well-balanced baseline (AUC 0.908) with the best precision-recall balance among the non-ensemble models. Its linear decision boundary handles this dataset well because the one-hot + standardized features are already fairly separable, but it can't capture the nonlinear interactions (e.g. `duration` × `poutcome`) that the tree-based models exploit. |
| Decision Tree | Matches Logistic Regression on accuracy/F1 and edges it out on recall, at the cost of a noticeably lower AUC (0.883). A single tree at `max_depth=8` overfits less than an unconstrained tree, but it still makes harder, more piecewise decision boundaries than the ensemble, which shows up as weaker ranking quality (AUC) despite decent hard-label accuracy. |
| kNN | The weakest of the "classic" models by MCC (0.603). Distance-based classification is diluted by the high-dimensional one-hot categorical space (11 categorical columns exploded to many binary dimensions), where Euclidean distance is a poor similarity measure — this is a known weakness of kNN on mixed categorical/numeric data. |
| Naive Bayes | Clearly the weakest model (MCC 0.430, recall 0.550) — it misses roughly half of true subscribers. GaussianNB's conditional-independence assumption is badly violated here (e.g. `duration` and `poutcome` are strongly correlated with each other and with the target), and treating one-hot categorical columns as if they were Gaussian-distributed numeric features further hurts its probability estimates. |
| Random Forest (Ensemble) | Best model on every single metric. Bagging many deep-ish trees over random feature subsets captures the nonlinear interactions Logistic Regression misses while averaging away the overfitting/instability that hurts the single Decision Tree, giving both the highest AUC (0.916) and by far the best recall/MCC (0.881 / 0.708) — i.e. it catches the most true subscribers while keeping false positives in check. |
| **Overall Winner for your dataset?** | **Random Forest (Ensemble)** — highest score on all 6 metrics, making it the clear choice for this dataset. |

## How to run

```bash
pip install -r requirements.txt
python train_models.py     # trains all 6 models, writes model/*.pkl + model/metrics.json + test_data.csv
streamlit run app.py       # launches the interactive app
Go to https://streamlit.io/cloud
Sign in using GitHub account
Click Create App
Select Git repository
Choose branch (main)
Select app.py
Click Deploy
```
